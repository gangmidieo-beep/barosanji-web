# 스마트스토어(네이버 커머스API) 등록 정보 검토 일괄 작업

스마트스토어 "등록 정보 검토"에 뜨는 **브랜드 / 제조사 / 속성 / 상품명** 미등록 항목을
API로 점검하고 일괄로 채우는 도구입니다.

## 1. 먼저 해야 할 일 — API 키 발급

이 작업은 **네이버 커머스API센터 자격증명이 있어야만** 돌아갑니다. 코드로는 못 만들어냅니다.

1. <https://apicenter.commerce.naver.com> 접속 → 스마트스토어 판매자 계정으로 로그인
2. **애플리케이션 등록** → 사용할 API 권한에 **상품(조회 + 수정)** 체크
3. 발급된 `애플리케이션 ID`(client_id) / `애플리케이션 시크릿`(client_secret)을 환경변수에 저장

```bash
# .env.local (로컬) 또는 레일웨이 환경변수
NAVER_COMMERCE_CLIENT_ID=...
NAVER_COMMERCE_CLIENT_SECRET=$2a$04$...
```

> client_secret은 `$2a$04$...` 형태의 bcrypt salt입니다. 그대로 넣으세요.
> 절대 코드나 커밋에 넣지 마세요.

## 2. 실행 순서

```bash
npm run naver:audit          # ① 현황 조회 (읽기 전용, 아무것도 바꾸지 않음)
npm run naver:learn          # ② 카테고리별 속성 템플릿 추출
npm run naver:apply          # ③ 수정 시뮬레이션 (dry-run — 무엇이 바뀔지만 출력)
npm run naver:apply -- --apply   # ④ 실제 수정
```

### ① audit — 현황 조회

전 상품을 원상품 조회까지 돌려 브랜드/제조사/속성 등록 상태를 표로 만듭니다.
결과는 `scripts/naver/out/audit.csv`, `audit.json` (git에 올라가지 않음).

상품 목록 조회 API는 브랜드/제조사/속성을 내려주지 않기 때문에, 상품 1건마다
원상품 조회를 한 번씩 해야 합니다. 208건이면 몇 분 걸립니다.

### ② learn — 속성 템플릿 추출

**커머스API에는 "이 카테고리에 어떤 속성이 있는지" 알려주는 공개 API가 없습니다.**
그래서 속성값 번호(`attributeSeq` / `attributeValueSeq`)를 알아낼 방법이 하나뿐입니다:
이미 속성이 채워진 상품을 조회해서 그 번호를 읽는 것.

따라서 **카테고리마다 상품 1건씩만 스토어 관리자 화면에서 손으로 속성을 입력**해두세요
(꽃게 1건, 문어 1건, 장어 1건, 전복 1건 … audit 결과의 카테고리 목록 참고).
그 뒤 `learn`을 돌리면 그 상품들에서 속성 번호를 읽어
`scripts/naver/attribute-templates.json`에 카테고리별 템플릿으로 저장합니다.

상품마다 값이 달라야 하는 속성(예: 중량)이 있으면 이 파일을 직접 손보면 됩니다.

### ③④ apply — 일괄 수정

`fill-config.json`의 브랜드/제조사 + `attribute-templates.json`의 속성으로 빈 칸을 채웁니다.

- 기본이 **dry-run**입니다. `--apply`를 붙여야만 실제로 수정합니다.
- **이미 값이 있는 항목은 절대 덮어쓰지 않습니다.** 비어 있는 칸만 채웁니다.
- 수정 직전에 원본을 `scripts/naver/out/backup/<originProductNo>.json`으로 통째 저장합니다.

## 3. 꼭 알아둬야 할 제약

**원상품 수정은 부분 수정이 아닙니다.**
요청에 넣지 않은 필드는 사라집니다. 네이버 공식 답변: *"생략 가능 명시가 없는 필드의 경우
값이 유지되지 않습니다."* (`detailContent`처럼 문서에 "생략 가능"이라 적힌 것만 유지됨)
그래서 이 도구는 항상 **조회 → 병합 → 전체 전송** 순서로만 동작합니다. 직접 PUT을 쏘지 마세요.

**카탈로그 매칭된 상품은 브랜드/제조사를 건드리면 안 됩니다.**
`catalogMatchingYn`이 `true`인 상품은 `naverShoppingSearchInfo`를 요청에 포함하면 처리가 거부됩니다.
이 도구는 해당 상품의 브랜드/제조사를 자동으로 건너뛰고 속성만 채웁니다.

**직접 입력한 브랜드/제조사는 네이버쇼핑 검색에 반영되지 않습니다.**
네이버 공식 안내상 직접 입력 방식은 "미등록" 표시만 없애줄 뿐이고,
실제 검색 노출은 카탈로그(모델) 매칭에서 나옵니다. 그리고 **브랜드만 단독으로 카탈로그
매칭하는 기능은 API에서 지원하지 않습니다.** 모델 매칭(`modelId`) 시 브랜드가 함께 연결되는데,
한번 연결한 `modelId`는 수정이 불가능합니다(상품 삭제 후 재등록만 가능).
→ 검토 표시를 없애는 게 목적이면 이 도구로 충분하고,
   검색 노출 개선이 목적이면 모델 카탈로그 매칭을 따로 검토해야 합니다.

**상품명 수정은 이 도구가 자동으로 하지 않습니다.**
상품명은 매출에 직결되고 규칙이 상품마다 달라서, 자동 생성 대신
`ProductPatch.name`으로 건별 지정하도록만 열어뒀습니다. audit.csv에서 대상 23건을 확인한 뒤
규칙을 정해주시면 그때 반영하는 편이 안전합니다.

## 4. 코드 위치

- `src/lib/naver-commerce.ts` — 인증(bcrypt 서명), 상품 조회/수정, 안전한 병합
- `scripts/naver/cli.ts` — audit / learn / apply 명령
